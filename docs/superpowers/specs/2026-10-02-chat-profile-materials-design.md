# 聊天画像素材输入设计

## 目标

补齐聊天工作台中“作品文案、近期评论、公开发言”三类用户授权素材的输入入口，让主播在录入大哥当前消息后，可以把已复制的公开/授权内容一并交给现有的 goutoujunshi 核心算法和 GLM-5.3 画像回复链路。

## 交互

- 画像素材区域默认折叠，标题明确说明“可选，不填也能生成”。
- 展开后提供三个多行输入框：作品文案、近期评论、公开发言/聊天片段。
- 每个输入框显示长度上限和“仅使用你有权提供的内容”提示；不提供抖音登录、抓取或自动发送能力。
- 点击“生成 AI 回复”时，当前素材与已确认消息历史一起提交；正在生成时素材输入和生成按钮保持明确的处理中状态。
- 生成成功后保留素材内容，候选仍通过“放入输入框”进入主播草稿，画像摘要显示证据边界。

## 数据流与持久化

1. `ChatWorkspace` 维护 `profileSources` 状态。
2. 本地记忆快照中保存 `profileSources`，切换维护对象时清空当前编辑态；服务端主播快照也保存同一字段。
3. `/api/profile/` 请求增加 `sources` 对象，字段名保持现有接口兼容：`works`、`comments`、`statements`。
4. 服务端继续用 `cleanText` 限长并由 `analyzeGoutoujunshi` 统一产生关系状态；客户端不能伪造算法判断。

## 边界与错误处理

- 三类素材均可为空；当前消息仍是生成前置条件。
- 只提交纯文本，不上传截图或平台凭据；截图仍走既有 OCR 确认流程。
- API 失败时保留素材和当前输入，不清空用户内容，错误提示沿用现有脱敏错误信息。
- 快照同步失败不阻断本地生成，页面展示已有服务端同步异常状态。

## 验收标准

- 聊天页存在默认折叠的画像素材入口和三个可编辑字段。
- 生成请求明确携带 `sources.works/comments/statements`，且仍携带当前消息、历史和授权确认。
- 本地/服务端快照可保存和恢复画像素材。
- 现有候选回填、复制、人工确认发送、OCR 和权限边界不回归。
- 新增定向契约测试、全量 `npm test` 和隔离生产构建通过。
