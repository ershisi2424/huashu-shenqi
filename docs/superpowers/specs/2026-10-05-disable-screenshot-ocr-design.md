# 暂停截图 OCR 功能设计

## 目标

暂时停止主播聊天页面的截图 OCR 使用，避免入口和前端请求干扰手动粘贴聊天流程；保留现有 OCR API、适配器、夹具和联调脚本，便于后续重新启用。

## 范围

- 聊天页面不渲染“导入截图识别”按钮、文件选择器和 OCR 预览。
- OCR 文件处理函数在关闭状态下立即返回，不读取文件、不发起 `/api/ocr` 请求。
- 使用一个明确的代码开关表达当前状态，默认值固定为关闭。
- `/api/ocr` 和 `lib/ocr` 保留，不在本次修改中删除或改变其服务契约。
- 手动输入、AI 候选回复、聊天记录和发送确认流程不受影响。

## 验收标准

1. OCR 功能开关默认值为 `false`。
2. 聊天组件只有在开关开启时才渲染 OCR 入口和预览。
3. 关闭状态下处理文件事件会立即结束，前端不会请求 `/api/ocr/`。
4. OCR API 现有契约测试仍然通过。
5. 聊天页面契约、核心测试和静态检查通过。

## 不在本次范围

- 删除 OCR 适配器、语言包、测试夹具或 `/api/ocr` 路由。
- 接入新的 OCR 引擎。
- 改动截图识别的左右气泡算法。
