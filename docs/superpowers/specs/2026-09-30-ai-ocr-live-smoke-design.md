# GLM-5.3 与 OCR 合成样本联调设计

## 背景与目标

当前应用已经具备智谱 GLM-5.3 画像/回复接口、`goutoujunshi` 本地核心判断、Tesseract OCR 适配器、健康检查和错误码映射，但现有自动化测试主要使用模拟响应，不能证明目标机器上的服务端、真实智谱 Key、网络请求、Tesseract 语言包和图片识别链路同时可用。

本阶段新增一个只在本机运行的联调脚本和一张合成聊天测试图片，用于验证真实链路。联调数据全部虚构，不读取抖音、不访问真实账号、不保存上传图片，也不把 API Key 写入日志或响应。

## 方案选择

采用“本地 CLI 联调脚本 + 合成样本 + 现有 API”方案，不新增网页诊断页面和公开诊断接口。

- 业务接口继续由 `/api/profile` 和 `/api/ocr` 负责，避免联调逻辑污染生产页面。
- 联调脚本通过本地 HTTP 访问正在运行的 Next.js 服务，验证真实序列化、鉴权、网络和错误响应。
- 离线契约测试继续保留，实机脚本只补上真实环境无法由单元测试证明的部分。
- 真实 API Key 只从运行环境读取；脚本不接受命令行明文 Key 参数，不打印请求头和完整请求体。

## 合成数据

AI 样本使用虚构的聊天内容，包含一条下班疲惫、主播承接和继续表达，验证普通承接场景、画像证据和多风格回复。

OCR 样本固定保存为 `fixtures/ocr-synthetic-chat.png`，由项目内的确定性生成脚本从内联 SVG 生成，不依赖真实聊天截图。图片中只包含虚构的左右聊天内容。OCR 结果默认仍标记为 `sender=brother`，脚本只验证识别和确认门禁，不绕过主播人工方向确认。

## 联调脚本

新增 `scripts/ai-ocr-smoke.cjs`，默认目标为 `http://127.0.0.1:3102`，支持 `--base-url` 覆盖地址，并提供以下阶段：

1. `GET /api/health`：确认服务可达、服务商为 zhipu、模型为 `glm-5.3`，只输出脱敏配置状态。
2. `POST /api/profile`：发送合成聊天素材和 `consent=true`，验证 GLM-5.3 实际返回、`goutoujunshi` 核心标识、核心动作、画像摘要、多元回复和后续分支。
3. `POST /api/ocr`：发送合成 PNG Data URL，验证 `requiresConfirmation=true`、`imageStored=false`、识别 blocks 结构和默认左侧归属。
4. 汇总结果：每一步输出通过/失败、耗时和下一步建议；失败时只输出错误码和可执行提示，不输出 Key、完整素材、Cookie 或原始响应。

脚本退出码：全部实机步骤通过为 `0`；服务不可达、Key 未配置、AI 错误、OCR 语言包/依赖错误或响应结构不符合预期均为非零。未配置 Key 时明确提示“跳过真实 AI 需先配置”，不能伪造成功。

## 错误分类

脚本沿用现有接口错误码，不根据自由文本猜测原因：

- `503` / `ZAI_API_KEY`：服务端未配置智谱 Key；
- `502`：Key 无效、无权限、超时或 AI 响应结构不合格；
- `429` / `ZHIPU_RATE_LIMIT`：智谱限流；`ZHIPU_ACCOUNT_ARREARS`：账户余额问题；
- `502` / `OCR_DEPENDENCY_UNAVAILABLE`：Tesseract 依赖不可用；
- `502` / 语言包或识别错误：提示检查首次下载、网络、`OCR_LANG` 和目标机器权限；
- `400`：测试图片格式、Data URL 或大小不符合接口约束；
- `401`：开启 `AUTH_REQUIRED` 时未登录，提示先在本机登录后再联调。

## 安全与隐私边界

- 只使用本地合成样本；脚本不读取文件夹中的聊天记录、截图或数据库内容。
- 不在 URL、标准输出、错误堆栈或测试产物中写入 API Key。
- 不新增远程可调用的诊断路由；脚本只访问用户指定的本地服务地址。
- OCR API 的 `imageStored=false` 和人工确认门禁保持不变。
- 本阶段不实现抖音读取、抖音发送、自动发送或自动决定主播回复。

## 验收标准

离线验收：

- 新增脚本契约测试先失败，再实现后通过；
- 现有 `npm test`、UI 静态检查和生产构建继续通过；
- 错误分类覆盖 Key 缺失、401、403、429/1113、OCR 依赖和图片校验。

实机验收（有 Key 和可联网目标环境）：

- `npm run smoke:ai-ocr` 返回退出码 0；
- 输出确认模型为 `glm-5.3`、服务商为 `zhipu`，并确认 `algorithmCore.name=goutoujunshi`；
- OCR 至少识别一条合成文本，返回人工确认标志且不保存图片；
- 失败时输出可执行诊断，不泄露秘密。

没有 Key 或语言包时的验收：

- 脚本返回非零并明确指出缺失项；
- 离线测试仍能通过；
- 不把“配置已读取”误报为“真实请求成功”。
