# 后台审批、操作日志与用户管理设计

日期：2026-09-30  
状态：用户已确认修正版结构，待实现

## 目标

将现有混合式运营后台拆成职责清晰的三个页面：超级管理员主页面只处理审批；操作日志按运营/主播分类查看完整操作；用户管理查看所有用户的使用状态，并提供停用、恢复和超级管理员二次确认后的永久删除。

## 页面结构

### `/admin` 审批中心

超级管理员登录后的主页面只显示：

- 待审批运营列表和批准/拒绝操作
- 待处理主播申请摘要（主播申请仍由所选运营审批；超级管理员可查看状态）
- 待处理数量、当前账号和权限范围
- 进入操作日志、用户管理和主播只读工作台的导航入口

不在主页直接展开全量聊天正文、操作时间线和全部用户列表，避免审批任务被复盘数据干扰。

运营访问 `/admin` 时显示自己的主播审批、账号管理和进入操作日志的入口；不能看到其他运营的数据，也不能进入用户管理。

### `/admin/audit` 操作日志

操作日志按操作者分组，而不是只按时间平铺：

- 最高管理员：全部运营、全部主播和系统操作。
- 运营：自己以及所辖主播的全部操作。
- 主播：无权访问操作日志页面和接口。

页面能力：

- 操作者分组卡片：姓名、角色、脱敏手机号、所属运营、最近操作时间、操作总数。
- 点击操作者进入该用户的完整时间线。
- 按动作、角色、时间范围、维护对象筛选；支持分页和搜索。
- `chat.message.append` 展开聊天正文，显示大哥/主播方向、消息状态、确认时间和发送时间。
- 展示快照同步、工作台查看、登录、审批、维护对象创建等动作。
- 只读；不提供修改、复制、代发、删除日志按钮。

### `/admin/users` 用户管理

仅 `super_admin` 可访问：

- 列出所有用户：姓名、脱敏手机号、角色、所属运营、账号状态、注册时间、最近登录、最近操作、维护对象数量、消息数量、当前会话数量。
- 支持按角色、状态、所属运营和关键词筛选。
- 支持查看某用户的只读主播工作台（运营只能从自己的下属主播进入；最高管理员可进入全部 active 主播）。
- `active` 用户可停用；`disabled` 用户可恢复。
- 停用不会删除任何聊天、快照或审计数据，立即撤销该用户全部会话。
- 永久删除仅超级管理员可用；执行前弹出二次确认，显示目标用户、角色、所属运营和待删除数据范围，再次点击确认后执行。
- 永久删除不可删除最后一个 active `super_admin`，也不能删除当前登录的最高管理员。

## 用户状态与使用状态

账号状态沿用 `pending`、`active`、`disabled`：

- `pending`：等待审批，不允许登录。
- `active`：允许登录和执行该角色权限内操作。
- `disabled`：禁止登录，历史数据保留。

使用状态为只读计算字段，不新增敏感追踪：

- `lastLoginAt`：最近一次成功登录时间。
- `lastActionAt`：最近一条审计动作时间。
- `activeSessionCount`：当前未过期会话数量。
- `brotherCount`：维护对象数量。
- `messageCount`：已同步聊天消息数量。
- `snapshotCount`：最新工作台快照数量。
- `usageStatus`：`active_recent`（近 24 小时有操作）、`active_7d`（近 7 天有操作）、`idle`、`never_used`。

不收集页面点击轨迹、键盘内容或设备指纹。

## 服务端接口

### 审批中心

保留现有审批接口，新增待处理摘要接口字段，不让 `/admin` 直接拉取完整审计和聊天正文。

### 操作日志

新增：

- `GET /api/ops/audit/actors/`：返回当前权限范围内按操作者聚合的统计。
- `GET /api/ops/audit/actor/:actorId/`：返回指定操作者的分页时间线和可关联聊天正文。
- 旧的 `GET /api/ops/audit/` 保留兼容，但后台新页面优先使用分组接口。

服务端从会话推导范围：运营不得通过 `actorId` 查询其他运营或其他组织；最高管理员可查询全部。所有参数使用参数化 SQL。主播访问返回 403。

### 用户管理

新增：

- `GET /api/admin/users/`：仅超级管理员，返回用户和使用状态统计，不返回密码哈希或完整手机号。
- `POST /api/admin/users/:id/status/`：仅超级管理员，动作 `disable` 或 `restore`；停用时撤销全部会话并写审计。
- `DELETE /api/admin/users/:id/`：仅超级管理员，执行永久删除；服务端二次确认令牌由页面确认接口获取，令牌短时有效且绑定目标用户，避免仅靠前端按钮绕过确认。
- `GET /api/admin/users/:id/workspace/`：仅超级管理员；运营通过对应的作用域接口查看自己下属主播工作台。

永久删除的事务范围：目标用户、其 sessions、工作台快照、维护对象和聊天消息；审计日志保留不可识别的操作者/目标快照与动作时间，不保留完整聊天正文。删除失败时整个事务回滚。

## 审计数据设计

审计动作增加：

- `workspace.snapshot.update`
- `workspace.snapshot.view`
- `user.disable`
- `user.restore`
- `user.delete`

为抵抗用户永久删除导致的外键失效，审计记录保留 `actor_snapshot_json` 和 `target_snapshot_json`：姓名、角色、脱敏手机号、所属运营名称；不保存密码、token、完整手机号或快照正文。旧记录迁移时从现有 users 表生成快照。

## 权限与安全边界

- 所有权限由服务端会话校验，不能通过 URL、隐藏按钮或修改请求体绕过。
- 运营日志只能看自己和所属主播；用户管理接口对运营一律 403。
- `disabled` 用户所有旧会话立即失效；恢复后必须重新登录。
- 永久删除需要当前会话是 active `super_admin`，不能删除自己，也不能删除最后一个 active `super_admin`。
- 删除确认只采用“二次点击确认”，但服务端仍需一次性短时确认令牌，避免直接构造 DELETE 请求绕过页面确认。
- 删除、停用、恢复、查看工作台和审计查看均写入审计；日志查询不写入聊天消息。

## 错误与交互状态

- 未登录 401；角色越权 403；目标不存在或不在作用域 404/403，不能泄露账号存在性。
- 停用/恢复/删除期间按钮锁定，显示处理中状态；成功后刷新列表和使用状态。
- 永久删除成功后用户从列表移除，显示明确结果；失败时显示“未完成，数据已回滚”。
- 页面支持空态、加载、错误、无权限和移动端单列布局。

## 测试与验收

1. `/admin` 只渲染审批区和导航，不直接渲染全量聊天或审计正文。
2. 审计分组：最高管理员全量、运营仅自己和下属主播、主播 403；正文关联和分页保持一致。
3. 用户列表统计准确：最近登录、最近操作、会话、维护对象、消息和快照数量。
4. 停用撤销会话且保留聊天/快照/审计；恢复后可重新登录。
5. 永久删除事务成功时清理用户工作台数据，审计脱敏记录保留；最后一个超级管理员和当前管理员删除被拒绝。
6. 所有 API 不能返回密码哈希、session、token、API key 或完整手机号。
7. 主播只读工作台入口遵守运营/最高管理员作用域，不出现可写控件。
8. 回归：`npm test`、`npm run build`、`git diff --check`，并完成真实 3102 权限链路验证。

## 验收标准

- 超级管理员主页面只处理审批。
- 操作日志能按某个运营或主播查看“做了什么”，并能展开授权范围内的聊天正文。
- 用户管理能看所有用户的使用状态，停用/恢复生效，永久删除有二次确认和服务端保护。
- 运营无法查看或管理其他组织，主播无法访问管理页面。
- 已有登录、审批、聊天同步、AI 生成和只读工作台能力不被破坏。
