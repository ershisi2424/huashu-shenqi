# 聊天删除操作设计

## 目标

聊天工作台只保留“修改”和“删除”两类消息操作；收藏、置顶从用户界面和主播工作流移除。消息与维护对象删除都必须二次确认，并在允许的情况下同步删除本地和服务端数据。

## 交互

- 每条消息只显示“修改”“删除”。
- “删除”使用二次确认弹窗；取消不改变消息，确认后立即从当前列表移除并显示结果。
- 删除消息失败时恢复原消息，并显示失败原因。
- 维护对象列表每项提供“删除维护对象”，二次确认内容明确包含对象昵称和“其全部聊天记录、草稿、画像素材”。
- 删除维护对象失败时恢复对象和其本地消息，不影响其他维护对象。
- 主播可以修改和删除自己的聊天；运营、超级管理员继续保持只读查看。访客模式沿用当前本地编辑能力。

## 数据流

1. 先保存待删除的本地快照，再更新 React 状态，保证界面立即反馈。
2. 有服务端身份且对象已同步时，调用消息或维护对象 DELETE API。
3. API 成功后保留本地删除结果；API 失败或网络异常时回滚快照并提示。
4. 无服务端身份或只有本地对象时，只删除当前账号作用域下的本地会话快照。
5. 删除维护对象必须清理该对象的消息、候选草稿、关系上下文和服务端关联记录。

## 兼容性

数据库中的收藏/置顶字段和旧 marks API 暂不删除，以兼容已有数据和旧客户端；新聊天界面不读取、不显示、不修改这些字段。

## 验收标准

- 聊天气泡下没有收藏、置顶按钮或状态文字。
- 删除消息和删除维护对象都无法通过一次误触直接完成。
- 删除一个对象不会影响同一主播的其他对象或其他主播同名对象。
- 主播删除后刷新页面，删除内容不再恢复。
- 全量测试和生产构建通过。
