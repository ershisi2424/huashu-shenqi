# 超级管理员 AI 服务配置设计

## 目标

为超级管理员提供一个受权限保护的服务配置页，集中维护智谱 GLM-5.3 的 API Key、模型和接口地址，让画像分析、回复生成和日常开场等 AI 能力统一走服务端 Provider 配置。

## 范围与边界

- 新增 `/admin/settings/`，只允许 `super_admin` 访问、读取和保存。
- 普通聊天页只保留脱敏服务状态，不再提供普通用户填写 API Key 的入口。
- Key 只写入服务端 `.env.local` 或 `AI_REPLY_CONFIG_PATH` 指向的配置文件，响应只返回 `configured`、模型和脱敏地址。
- 保存后更新当前进程环境变量，并提示重启服务；实际可用性必须通过独立测试调用确认。
- OCR 仍由本地 Tesseract 适配器完成，不把 OCR 误报为 GLM-5.3 调用。
- 不接入抖音后台、不自动发送消息、不保存 Key 到数据库或浏览器存储。

## 页面与交互

- 后台导航增加“服务配置”，仅超级管理员渲染。
- 配置卡包含 API Key 密码输入框、模型、接口地址、保存配置和测试调用。
- 状态分为未配置、已读取配置、实际调用成功、Key 无效、无权限、限流/欠费和服务不可达。
- 保存期间按钮进入处理中，成功和失败均展示明确反馈；Key 留空表示保留已有值。
- 移动端收敛为单列表单，输入和按钮保持可触控尺寸。

## 服务端结构

- `lib/ai-provider.cjs` 负责读取、校验和调用统一的智谱 Provider，业务 API 不再自行拼接 Key 与 endpoint。
- `pages/api/admin/settings.js` 负责超级管理员鉴权、脱敏读取和保存配置。
- `pages/api/admin/settings/test.js` 使用最小合成请求验证真实 Provider 权限，返回脱敏状态码。
- `/api/health` 复用 Provider 的配置状态；`/api/profile` 复用 Provider 发起 GLM-5.3 请求。
- 其他 AI 入口通过同一 Provider 接口接入，不改变现有授权确认、限流和内容安全边界。

## 错误处理

- 非超级管理员返回 `401/403`，不泄露配置内容。
- 配置无效返回明确字段错误；Key 不会出现在日志和 JSON 响应。
- Provider 测试按 401、403、429、欠费、超时和结构异常映射为脱敏错误码。
- 配置读取成功不等于真实调用成功，页面分别展示两种状态。

## 验证

- 先写失败测试：超级管理员可读写、普通角色拒绝、响应不泄露 Key、配置校验、测试调用错误映射。
- 运行已有设置、健康检查、生成契约和认证测试，随后运行全量 `npm test`。
- 使用隔离目录执行生产构建和 UI 规则检查；不以 Key 缺失环境宣称真实 AI 调用通过。
