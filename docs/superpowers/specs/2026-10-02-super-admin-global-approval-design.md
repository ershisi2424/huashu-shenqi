# 超级管理员全量审批设计

## 目标

让 `super_admin` 在审批中心直接查看并批准/拒绝全部待审批账号，包括运营注册申请和主播注册申请。运营仍只能处理自己绑定的主播申请。

## 权限与数据流

- `/api/auth/approvals/` 继续只处理运营申请，仅允许 `super_admin`。
- `/api/auth/anchor-approvals/` 扩展为 `operator` 与 `super_admin` 可访问：运营只查询自己的主播，最高管理员查询全部待审批主播。
- 服务端审批方法依据审批人真实数据库角色判断，不信任前端传入角色；主播的 `operator_id` 绑定关系不因最高管理员审批而改变。
- 每次批准/拒绝继续写入原有审计动作，保留实际审批人快照和目标账号快照。

## 界面

- 超级管理员审批中心展示两条独立队列：待审批运营、待审批主播；每条队列分别显示数量和批准/拒绝操作。
- 运营界面保持现有待审批主播队列，不展示其他运营的申请。
- 成功、失败、加载和空状态沿用现有审批中心样式；不新增账号创建或自动审批能力。

## 验证

- 存储测试覆盖最高管理员批准/拒绝其他运营名下主播、运营越权仍失败。
- API 测试覆盖最高管理员读取和操作主播申请、运营范围不变。
- UI 契约覆盖两条队列和按申请类型调用接口。
