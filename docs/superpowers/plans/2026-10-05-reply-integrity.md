# 回复完整性与目标竞态阶段

## 目标

让一次 AI 生成只服务于“当前主播账号 + 当前维护对象 + 当前已确认大哥消息”，并保证历史/快照不会接受浏览器伪造的来源或正文。

## 实施顺序与结果

- [x] 先新增 `test-chat-source-boundary.cjs`，确认旧实现会接受空来源、跨对象来源、未确认来源和篡改正文。
- [x] 在数据层集中实现已确认来源校验，生成上下文、回复历史、工作台候选快照复用同一规则。
- [x] 在 API 层把来源错误映射为 409，客户端可以区分输入边界错误和服务不可用。
- [x] 在前端对象切换时失效旧生成批次，清空上一对象的画像、分析、候选；历史异步回写带批次校验。
- [x] 定向测试通过后执行 `npm test` 和 `git diff --check`。

## 验收证据

- 来源边界、回复历史、工作台快照、删除兼容、角色工作区和游客 profile 定向测试通过。
- 全量验证入口实际发现并执行 86 项测试，86/86 通过。
- 未操作真实服务、真实数据库或外部模型调用；浏览器挂载端到端、Windows 10 局域网和真实供应商仍属于后续阶段。

## 后续准入

下一阶段才能处理认证默认强制、登录限流、迁移版本/备份恢复和真实浏览器回归；若本阶段回归失败，不新增业务功能。
