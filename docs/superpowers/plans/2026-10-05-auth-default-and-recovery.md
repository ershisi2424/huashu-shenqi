# 认证默认策略与恢复边界

## 目标

让生产构建在没有显式覆盖时默认要求登录，同时保留开发环境的本地预览兼容性；统一健康检查和 AI 入口读取同一策略，避免页面显示“需要登录”而 API 仍匿名放行。密码重置、恢复和密钥轮换不在本阶段伪造完成，先固定边界与测试入口。

## 本阶段范围

1. `NODE_ENV=production` 且未设置 `AUTH_REQUIRED` 时默认返回 true。
2. `AUTH_REQUIRED=true/false` 显式配置优先级最高。
3. 健康接口、AI 接口和受保护接口使用同一 `authRequired()` 判断，避免直接读取环境变量造成策略分叉。
4. 增加策略契约测试，覆盖生产默认、开发默认和显式覆盖。
5. 记录恢复流程尚未实现的生产边界，不读取或输出密码。

## 验收

- 先运行 `node test-auth-default.cjs`，旧实现应失败；实现后通过。
- `npm test` 全量通过。
- 独立副本 `npm run build` 通过。
- `git diff --check` 通过。

## 未完成边界

- 密码重置/恢复需要一次性令牌、超级管理员二次确认、审计和失效测试。
- 生产启用反向代理时还需把 `AUTH_COOKIE_SECURE=true`、可信代理和 HTTPS 一并验收。
