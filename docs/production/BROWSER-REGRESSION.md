# 真实浏览器回归方案

## 目标

用一次性的合成账号、临时数据库和临时端口验证登录、权限、聊天保存、刷新恢复、候选回复来源绑定以及账号隔离。该流程不读取、不修改正在运行的 3102 服务，也不使用项目目录下的真实账号数据库。

当前仓库没有引入 Playwright、Cypress 或其他浏览器自动化大依赖。下面的契约先固定环境边界，浏览器驱动由后续阶段单独评估；静态测试和 Node HTTP 测试不能替代真实浏览器验收。

## 浏览器启动前置检查

在启动任何浏览器驱动前，先在临时副本执行：

```bash
node scripts/browser-regression-preflight.cjs
```

该命令只解析环境变量和路径，不启动服务、不打开数据库、不读取 Cookie。成功只输出临时目标摘要；失败输出稳定 `BROWSER_PREFLIGHT_FAILED <CODE>`，不会回显密码、Token、Cookie、手机号、数据库绝对路径或 API Key。

前置检查会拒绝：

- 缺少 `NODE_ENV=test`、`AUTH_REQUIRED=true` 或 `AUTH_COOKIE_SECURE=false`；
- `BASE_URL` 缺失、非回环地址、无端口或端口 `3102`；
- `AUTH_DB_PATH` 位于项目根目录/正式 `data` 目录、使用 `:memory:` 或非 SQLite 扩展；
- provider key、浏览器 Cookie 或 Playwright storage state 环境变量。

## Agent Browser 冒烟入口

完成 preflight 后，可在已经启动的临时服务上显式开启浏览器冒烟：

```bash
BROWSER_REGRESSION_EXECUTE=true npm run browser:smoke
```

冒烟器使用隔离的 `agent-browser` session，只执行“打开 `/login/`、等待网络空闲、确认仍在目标 origin、关闭 session”四步；不自动输入账号、不读取 Cookie、不调用 AI。未设置显式开关时返回 `BROWSER_RUNNER_NOT_ENABLED`；未安装 `agent-browser` 时返回 `AGENT_BROWSER_NOT_FOUND`。这两个结果都不能记为浏览器验收通过。

## 安全前置条件

运行前必须满足以下条件：

```text
NODE_ENV=test
AUTH_REQUIRED=true
AUTH_COOKIE_SECURE=false        # 仅限 127.0.0.1 的 HTTP 临时服务
AUTH_DB_PATH=<临时目录>/auth.sqlite
BASE_URL=http://127.0.0.1:<临时高端口>
```

- `BASE_URL` 必须明确指定，不能使用 `http://127.0.0.1:3102`。
- 临时端口必须由测试进程分配，并在回归结束后释放；不复用开发服务端口。
- `AUTH_DB_PATH` 必须位于临时目录，不能是 `data/auth.sqlite` 或任何生产备份路径。
- 不向测试进程传入真实智谱 Key、正式 Cookie、真实手机号或生产会话。
- 测试日志只能输出状态码、错误码和合成用户标识，不输出密码、Token、Cookie 或数据库内容。

## 推荐执行顺序

1. 将项目复制到新的临时目录，排除 `.next`、`data/auth.sqlite*` 和 `.env.local`；在副本执行 `npm ci` 和 `npm run build`。
2. 创建临时数据库目录，设置上面的环境变量；用合成手机号和临时密码执行 `scripts/bootstrap-admin.cjs`。
3. 执行 `node scripts/browser-regression-preflight.cjs`，只有退出码 0 才继续。
4. 在临时高端口启动：

   ```powershell
   npm run start -- -H 127.0.0.1 -p <临时高端口>
   ```

5. 使用浏览器访问临时 `BASE_URL/login/`，按以下顺序建立测试数据：

   - 最高管理员登录；
   - 提交并批准合成运营账号；
   - 由运营创建或批准合成主播账号；
   - 主播登录，新增合成维护对象；
   - 写入一条大哥消息，生成候选并选择一条；
   - 刷新页面，确认对象、消息和候选只恢复当前主播的数据；
   - 切换到另一个主播，确认不能看到前一个主播的对象、消息或回复历史；
   - 用运营和最高管理员只读查看主播工作台，确认没有越权修改入口；
   - 用游客手机号进入临时工作台，确认只能看到自己的临时数据。

6. 浏览器验证结束后关闭服务，删除临时目录和临时数据库；不能调用任何针对 3102 或正式数据库的清理命令。

## 必须覆盖的浏览器断言

### 登录与会话

- 未登录访问 `/chat/` 只能进入登录界面，不能短暂显示旧账号聊天正文。
- 登录成功后刷新页面，仍保持当前账号作用域；退出后不得恢复旧账号本地状态。
- 游客和正式账号切换后，两个作用域的维护对象、消息和候选不混用。

### 权限与数据归属

- 运营只能查看和管理自己名下主播；跨运营访问返回拒绝。
- 最高管理员可以审批和查看授权范围内的内容，但不能通过只读查看页代替主播写入聊天。
- 服务端始终根据会话解析用户，浏览器传入的 `actor`、`role` 或 `owner` 不能扩大权限。

### 回复完整性

- 选择候选不触发整页刷新，已生成候选不会闪退或消失。
- 生成请求返回后必须仍绑定当前维护对象和当前来源消息；切换对象期间返回的旧请求必须丢弃。
- 刷新后历史候选只能恢复其真实来源消息，不能出现“当前没有输入却显示旧消息回复”的情况。
- 删除或修改来源消息期间的旧生成结果不能覆盖最新内容。

## 当前环境证据

本阶段只读检查确认：

- 测试 runner 已为每个子进程注入临时 `AUTH_DB_PATH`，并过滤真实 Key、Cookie、数据库路径和 `NODE_OPTIONS`。
- 生产构建可在独立副本完成。
- 当前受控环境尝试在 `127.0.0.1:3210` 启动独立 `next start` 时返回 `listen EPERM`。这属于环境禁止新建监听端口，不能据此宣称应用运行时失败；同时没有触碰 3102。
- 因此本阶段不伪造浏览器通过结果；需要在允许临时回环监听的环境，或 Windows 10 局域网副本上执行上面的真实浏览器流程。
- 本阶段已新增并通过无端口依赖的 preflight；这只证明危险目标会被阻断，不代表真实浏览器流程已通过。
- 本阶段新增了可选 `npm run browser:smoke` 适配层；当前环境未安装 `agent-browser`，因此真实浏览器冒烟仍保持 PENDING。

## 后续实现边界

后续若引入浏览器驱动，应作为可选开发依赖并单独命令运行，不进入默认 `npm test` 的生产运行路径。驱动必须接收显式 `BASE_URL` 和 `AUTH_DB_PATH`，在启动前拒绝 3102、项目正式数据库和任何正式 Cookie；失败时留下状态码、错误码和环境原因，不留下凭据。
