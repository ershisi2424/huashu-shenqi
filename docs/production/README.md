## 模块化约束

- 保留 Next.js Pages Router，渐进拆分为模块化单体，不先引入微服务或整体更换认证框架。
- 前端：页面只组合组件；认证、聊天目标、生成状态、保存状态分别封装。数据库和密钥不进入客户端。
- API：只做输入校验、会话身份解析、授权、业务服务调用与错误映射。身份以服务端会话为准，不信任客户端 actor/role。
- 业务：auth、approvals、chat、generation、maintenance、review、audit、usage 模块各自管理业务规则。
- 数据层：repository 接口隔离 SQLite 细节；引入有版本迁移、备份和恢复验收，再考虑更换数据库。
- 回复：生成结果绑定 owner + brother + message ID + message revision + generation ID，旧请求不能覆盖新请求；无匹配目标不得降级为旧候选。
- 管理者查看主播数据必须保留权限范围和审计；查看权限不等于代主播修改聊天的权限。
- 登录凭据只能保存不可逆密码哈希，超级管理员使用重置流程，不提供读取明文密码功能。
- 外部依赖逐项引入、固定版本、记录许可证和用途，不整仓移植。
